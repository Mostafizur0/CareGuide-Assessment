## Part 1 — Fix the node-agent CronJob (the only broken component)

### Root cause (already diagnosed)

The CronJob container fails with:

```
ERROR: Unable to lock database: Permission denied
ERROR: Failed to open apk database: Permission denied
```

`apk add` must write `/lib/apk/db` and lock it. The pod runs `runAsUser: 10001` with `readOnlyRootFilesystem: true`, so apk cannot create its database. Verified empirically: the same `apk add` succeeds as root and fails as uid 10001 under the hardened context. The failed Job pods are deleted by the Job controller within ~20s, so logs must be captured from a standalone equivalent Pod.

### Chosen fix — bake the runtime dependencies into a purpose-built image

Approved plan revision 1 chose "alpine:3.21 + install bash/procps/coreutils at run time". That decision was made before the permission conflict was known, and it cannot work with the approved security context. The fix keeps every security property (non-root uid 10001, `readOnlyRootFilesystem`, `drop: [ALL]`, `allowPrivilegeEscalation: false`) and removes the runtime package manager entirely:

- Write `system_health_app/Dockerfile` (the file exists but is empty — it is the natural home) as a small image on `alpine:3.21` with `bash`, `procps` and `coreutils` installed **at build time**. `procps` is mandatory: the script calls `ps -eo pid,comm,%mem --sort=-%mem`, which BusyBox `ps` does not support.
- `k8s/06-cronjob.yaml`: container image becomes the node-agent image; the `command` becomes `exec /opt/scripts/system_health.sh --json` with **no** `apk add`; the `/tmp` and `/var/cache/apk` emptyDirs are dropped (no writable root needed); the ConfigMap mount, `hostPID: true`, the hostPath log volume, resource requests/limits and `HEALTH_LOG_FILE` stay exactly as approved.
- Build locally as `careguide/system-health-agent:1.0.0`, `kind load docker-image` it into both nodes, and document the GHCR publication path for production.
- Keep `06-cronjob.yaml` self-contained: the node agent keeps its own namespace `careguide-system-health-nodeagent` (Pod Security `privileged`) so the application namespace can stay enforced at `restricted`. The application namespace label `pod-security.kubernetes.io/enforce: restricted` is already applied and verified.

**Rejected alternatives (record the reason in the README Design Decisions):** mounting emptyDirs over `/lib/apk` and `/etc/apk` breaks apk signature verification or needs `--allow-untrusted`; running the container as root to let apk write would discard the approved security context; `apk --root` into an emptyDir resolves no packages unless the repositories file and keys are copied in first.

### Verification for Part 1

```
kubectl -n careguide-system-health-nodeagent create job --from=cronjob/system-health-check manual-1
kubectl -n careguide-system-health-nodeagent logs job/manual-1
kubectl -n careguide-system-health-nodeagent exec <pod> -- cat /var/log/system-health/health_log.txt
```

Pass = the job completes, the log line contains `status=healthy` (or `warning`), and the hostPath file persists on the node.

## Part 4 — `k8s/README.md` (approved plan task t7)

Covers: prerequisites, apply order, the two-namespace split and why, controller prerequisites (Traefik chart install, metrics-server for the HPA), how the image is published and pulled, production secret replacement (`kubectl create secret` / Sealed Secrets / External Secrets Operator), every verification command, the memory-unit note, and the rollback runbook.

Key facts to carry (all verified during implementation):

- **Memory units.** Kubernetes' `m` suffix means *milli*, so `600m` = 0.6 **bytes**, not 600 MB. The API server warns `fractional byte value "600m" is invalid`. The manifests use binary units: Deployment `256Mi` request / `600Mi` limit; CronJob `64Mi` / `128Mi`; LimitRange defaults match.
- **CPU limit.** The task asked for `cpus: 1m`; `1m` is one millicore, below the `500m` request, and the API server rejects a limit lower than the request. The manifests use `cpu: "1"`.
- **Namespace split.** `careguide-system-health` is enforced at Pod Security `restricted`; the node agent lives in `careguide-system-health-nodeagent` at `privileged` because `hostPID`/`hostPath` are forbidden even by `baseline`. Real Pod Security exemptions are configured in the AdmissionController config, not as namespace labels — there is no per-namespace exemption label.
- **Image.** `ghcr.io/mostafizur0/careguide-assessment:1.0.0` is **not published** (the registry returns `denied` for an anonymous pull). Locally the image is built from `app/` and loaded into kind with `kind load docker-image`.
- **HPA.** Requires metrics-server; without it the HPA reports `<unknown>` and cannot scale. Documented as a cluster prerequisite, not a manifest defect.
- **Rollback.** `kubectl rollout undo deployment/system-health`, `rollout history`, `rollout status --timeout=300s`; `revisionHistoryLimit: 10`, `progressDeadlineSeconds: 600`.
